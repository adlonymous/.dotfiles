Core design principles and constraints that govern the system.

## Detail Over Decoration

Every element serves a purpose. Visual details emerge from functional constraints, not decoration.

- Ink filters exist to add material texture, not decoration
- Spacing derives from typography, not arbitrary grids
- Motion reveals structure, doesn't distract
- Every pixel justifies its presence

## Little First

Start with the smallest, simplest version. Add only what's necessary.

- Begin with plain text
- Add structure when needed
- Introduce color sparingly
- Expand only under pressure

See `policy/little-first.md` for details.

## Made Live

Work is published live, not staged in private. The site is the workshop.

- Write in public
- Iterate in production
- Show the process
- No staging environment

See `policy/made-live.md` for details.

## Every Word is Mine

All writing is first-person, owner voice. No AI-written content, no third-person marketing copy.

- "I designed" not "Ahmed designed"
- "my work" not "his work"
- Every sentence is deliberate
- No content generated by AI without heavy editing

See `memories/every-word-is-mine.md` for details.

## No Modals for Books

Library and reading experiences don't use modal dialogs. Books deserve full-screen attention or inline context, never trapped in a modal.

See `memories/no-modals-for-books.md` for details.

## Commercial Assets

Three commercially licensed assets are used:
- Shinka (serif)
- Kult Luxury (wordmark)
- Amicons (icons)

Anyone using this harness must license these separately or use fallbacks. Never bundle proprietary assets.

## Foundation Variables

User-adjustable sliders control the visual intensity:

- `--fnd-energy` (0–1): motion speed
- `--fnd-texture` (0–1): ink displacement & grain
- `--fnd-focus` (0–1): blur amount
- `--fnd-density` (0–1): spacing tightness

These affect the entire system. Default values balance readability with texture.

## Theme Switching

Four themes are available:
- Light (default)
- Dark
- Marathon Dark (neon lime)
- Marathon Light (neon lime)

Marathon themes support accent color variants (lime, cyan, red, amber, green).

Users can switch themes and accents via Settings. Preference persists in localStorage.

## Accessibility

- Semantic HTML throughout
- ARIA labels on icon buttons
- Focus rings on all interactive elements
- Skip link to content
- Respects `prefers-reduced-motion`
- Keyboard navigation for all UI

## Performance

- No heavy frameworks (vanilla JS)
- CSS custom properties for theming
- WebGL canvas for visual effects (degrades gracefully)
- Static site, hash-based routing
- Minimal JavaScript payload

## Progressive Enhancement

- Works without JavaScript (noscript message)
- Works without WebGL (falls back to CSS)
- Works without custom fonts (serif/sans fallbacks)
- Works on narrow viewports (responsive)

## Design Tokens

All values are tokenized:
- Colors: semantic (`--ink`, `--paper`, `--accent`)
- Spacing: responsive (`--gap`, `--para`, `--stack`)
- Typography: font stacks with fallbacks
- Motion: foundation-driven timing

Never use raw hex or px values in component styles. Always reference tokens.
